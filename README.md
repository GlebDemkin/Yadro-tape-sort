# yadro-tape-sort

  

## Описание проекта

  

Проект реализует консольное приложение на C++ для сортировки данных на устройстве хранения типа лента.

  

Лента рассматривается как устройство последовательного доступа. В каждый момент времени считывающая/записывающая головка находится только над одной ячейкой. Программа может прочитать или записать значение только в текущей ячейке, а для перехода к другой ячейке нужно сдвигать ленту влево или вправо.

  

Основная особенность задачи заключается в том, что входная лента может быть очень большой, а объём оперативной памяти ограничен. Поэтому программа не загружает все данные целиком в память, а использует внешнюю сортировку слиянием и временные ленты.

  

В текущей реализации:

  

- элементы ленты имеют тип `std::int32_t`;

- одна ячейка ленты занимает 4 байта;

- основная программа работает с бинарными файлами ленты;

- для удобной проверки добавлена утилита `tape_tool`, которая преобразует обычные текстовые файлы в бинарные ленты и обратно;

- временные ленты создаются в папке `tmp`;

- задержки операций ленты и лимит памяти задаются через файл `config.txt`.

## Основная идея решения

  

Обычная сортировка через загрузку всех чисел в `std::vector` не подходит, потому что по условию объём входной ленты может быть больше доступной оперативной памяти.

  

Поэтому используется внешняя сортировка слиянием.

  

Алгоритм работает так:

  

1. Входная лента читается небольшими блоками.

2. Размер блока ограничен параметром `memory_limit_bytes`.

3. Каждый блок сортируется в оперативной памяти.

4. Отсортированный блок записывается во временную ленту.

5. После чтения всей входной ленты временные ленты попарно сливаются.

6. Слияние повторяется, пока не останется одна полностью отсортированная временная лента.

7. Итоговая временная лента копируется в выходную ленту.

  

Например, если входная лента содержит:

  

```text

2 4 3 1 3 5

```

  

а в память помещается только 3 числа, то программа сначала создаёт временные ленты:

  

```text

level_0_run_0.bin = 2 3 4

level_0_run_1.bin = 1 3 5

```

  

Затем они сливаются:

  

```text

level_1_run_0.bin = 1 2 3 3 4 5

```

  

После этого результат записывается в выходную ленту.

  

## Формат данных

  

Основная программа `yadro_tape_sort` работает с бинарным форматом.

  

Каждый элемент ленты хранится как `std::int32_t`.

  

Это означает:

  

```text

1 элемент = 4 байта

```

  

Например, последовательность:

  

```text

2 4 3 1 3 5

```

  

в бинарном файле хранится не как текстовые символы, а как набор 32-битных целых чисел.

  

Такой формат удобен для эмуляции ленты с фиксированным размером ячейки. Каждая ячейка имеет одинаковый размер, поэтому позиция ячейки в файле легко вычисляется:

  

```text

байтовое смещение = номер ячейки * sizeof(std::int32_t)

```

  

Для удобства ручной проверки в проект добавлена отдельная утилита `tape_tool`.

  

Она умеет:

  

```text

encode — преобразовать input.txt в input.bin

decode — преобразовать output.bin в output.txt

print  — вывести бинарную ленту в консоль

```

## Описание основных файлов

  

### `include/ITape.h`

  

Файл содержит общий интерфейс ленты.

  

Интерфейс `ITape` описывает операции, которые должна поддерживать любая лента:

  

```cpp

read()

write()

moveLeft()

moveRight()

rewindToBegin()

rewindToEnd()

isAtBegin()

isEnd()

position()

size()

```

  

Главная идея этого интерфейса в том, что сортировщик не должен знать, как именно устроена лента внутри.

  

Он работает только через абстрактные операции чтения, записи и перемещения.

  

В текущей реализации тип одного элемента ленты задан так:

  

```cpp

using ValueType = std::int32_t;

```

  

То есть каждая ячейка ленты хранит одно 32-битное знаковое целое число.

  

### `include/FileTape.h`

  

Файл содержит объявление класса `FileTape`.

  

`FileTape` реализует интерфейс `ITape` и эмулирует ленту с помощью обычного бинарного файла.

  

Класс хранит:

  

```text

filePath_         — путь к файлу ленты;

config_           — настройки задержек;

file_             — файловый поток;

currentPosition_  — текущая позиция головки;

tapeSize_         — количество ячеек на ленте.

```

  

Класс поддерживает два режима открытия:

  

```cpp

ReadWriteExisting

CreateNew

```

  

`ReadWriteExisting` используется для существующих лент, например для входного файла.

  

`CreateNew` используется для создания новой ленты, например для выходного файла или временной ленты.

  

### `src/FileTape.cpp`

  

Файл содержит реализацию файловой ленты.

  

Основные функции:

  

`prepareExistingFile()` — проверяет, что существующий файл ленты корректен. Размер файла должен делиться на размер одного элемента ленты.

  

`createEmptyFile()` — создаёт новый бинарный файл нужной длины и заполняет его нулями.

  

`read()` — читает значение из текущей ячейки.

  

`write()` — записывает значение в текущую ячейку.

  

`moveLeft()` — сдвигает головку на одну позицию влево.

  

`moveRight()` — сдвигает головку на одну позицию вправо.

  

`rewindToBegin()` — перематывает ленту в начало.

  

`rewindToEnd()` — перематывает ленту на последнюю ячейку.

  

`currentByteOffset()` — вычисляет байтовое смещение текущей ячейки в файле.

  

Например, если текущая позиция равна `3`, а один элемент занимает `4` байта, то смещение будет:

  

```text

3 * 4 = 12 байт

```

  

### `include/TapeConfig.h`

  

Файл содержит структуру `TapeConfig`.

  

Она хранит настройки программы:

  

```cpp

std::uint64_t readDelayMs;

std::uint64_t writeDelayMs;

std::uint64_t moveDelayMs;

std::uint64_t rewindDelayMs;

std::size_t memoryLimitBytes;

bool verbose;

```

  

Поля задержек отвечают за искусственную задержку операций ленты.

  

`memoryLimitBytes` задаёт лимит памяти для блока, который сортируется в оперативной памяти.

  

`verbose` включает или выключает подробный вывод в консоль.

  

### `src/TapeConfig.cpp`

  

Файл содержит реализацию чтения конфигурационного файла.

  

Файл `config.txt` имеет формат:

  

```text

key=value

```

  

Например:

  

```text

read_delay_ms=0

write_delay_ms=0

move_delay_ms=0

rewind_delay_ms=0

memory_limit_bytes=12

verbose=true

```

  

Функция `loadFromFile()` читает конфигурационный файл, разбирает строки и заполняет объект `TapeConfig`.

  

Если строка содержит неизвестный ключ или некорректное значение, программа выдаёт ошибку.

  

### `include/TapeSorter.h`

  

Файл содержит объявление класса `TapeSorter`.

  

`TapeSorter` отвечает за сам алгоритм сортировки.

  

Основные методы:

  

`sort()` — главный метод сортировки.

  

`createSortedRuns()` — создаёт начальные отсортированные временные ленты.

  

`mergeLevel()` — сливает временные ленты одного уровня.

  

`mergeTwoRuns()` — сливает две конкретные отсортированные временные ленты.

  

`copyRunToOutput()` — копирует итоговую временную ленту в выходную ленту.

  

`makeRunPath()` — формирует имя временного файла по номеру уровня и номеру ленты.

  

`calculateBlockSize()` — считает, сколько элементов можно держать в памяти одновременно.

  

### `src/TapeSorter.cpp`

  

Файл содержит реализацию внешней сортировки слиянием.

  

Сначала входная лента читается блоками. Каждый блок сортируется в памяти и записывается во временную ленту уровня `0`.

  

Имена временных лент формируются так:

  

```text

tmp/level_0_run_0.bin

tmp/level_0_run_1.bin

tmp/level_0_run_2.bin

```

  

После этого временные ленты попарно сливаются.

  

Например:

  

```text

level_0_run_0.bin + level_0_run_1.bin -> level_1_run_0.bin

level_0_run_2.bin + level_0_run_3.bin -> level_1_run_1.bin

```

  

Слияние продолжается, пока не останется одна временная лента.

  

При слиянии двух лент в памяти хранятся только два текущих значения:

  

```text

leftRunValue

rightRunValue

```

  

То есть две временные ленты не загружаются в память целиком.

  

### `src/main.cpp`

  

Основная точка входа программы.

  

Программа принимает аргументы командной строки:

  

```text

yadro_tape_sort <input_file> <output_file> [config_file]

```

  

Например:

  

```powershell

.\out\build\msvc-debug\bin\yadro_tape_sort.exe bin/input.bin bin/output.bin config.txt

```

  

`main.cpp` делает следующее:

  

1. Проверяет аргументы командной строки.

2. Загружает настройки из `config.txt`.

3. Создаёт входную файловую ленту.

4. Создаёт выходную файловую ленту.

5. Создаёт объект `TapeSorter`.

6. Запускает сортировку.

  

### `src/tape_tool.cpp`

  

Вспомогательная консольная утилита для работы с бинарными лентами.

  

Основная программа работает с бинарными файлами, поэтому для удобства добавлена отдельная утилита.

  

Она поддерживает команды:

  

```text

encode

decode

print

```

  

Команда `encode` преобразует текстовый файл с числами в бинарную ленту:

  

```powershell

.\out\build\msvc-debug\bin\tape_tool.exe encode txt/input.txt bin/input.bin

```

  

Команда `decode` преобразует бинарную ленту обратно в текстовый файл:

  

```powershell

.\out\build\msvc-debug\bin\tape_tool.exe decode bin/output.bin txt/output.txt

```

  

Команда `print` выводит содержимое бинарной ленты в консоль:

  

```powershell

.\out\build\msvc-debug\bin\tape_tool.exe print bin/output.bin

```

  

### `tests/TapeSorterTests.cpp`

  

Файл содержит юнит-тесты.

  

Тесты проверяют:

  

```text

сортировку с повторяющимися значениями;

сортировку отрицательных чисел;

сортировку уже отсортированных данных;

сортировку обратно отсортированных данных;

ошибку при слишком маленьком лимите памяти.

```

  

В тестах создаются маленькие бинарные ленты, запускается сортировщик, после чего результат сравнивается с ожидаемым.

  

## Конфигурационный файл

  

Пример `config.txt`:

  

```text

read_delay_ms=0

write_delay_ms=0

move_delay_ms=0

rewind_delay_ms=0

memory_limit_bytes=12

verbose=true

```

  

Описание параметров:

  

`read_delay_ms` — задержка чтения одной ячейки в миллисекундах.

  

`write_delay_ms` — задержка записи одной ячейки в миллисекундах.

  

`move_delay_ms` — задержка сдвига ленты на одну позицию.

  

`rewind_delay_ms` — задержка перемотки ленты.

  

`memory_limit_bytes` — лимит памяти для блока, который сортируется в оперативной памяти.

  

Например:

  

```text

memory_limit_bytes=12

```

  

Если один элемент занимает 4 байта, то в память помещается:

  

```text

12 / 4 = 3 элемента

```

  

`verbose` — режим подробного вывода.

  

Если указано:

  

```text

verbose=true

```

  

программа будет выводить информацию о создании временных лент, слиянии и удалении временных файлов.

  

Пример вывода:

  

```text

Created tmp directory: tmp

Created run: tmp\level_0_run_0.bin

Created run: tmp\level_0_run_1.bin

Merged: tmp\level_0_run_0.bin + tmp\level_0_run_1.bin -> tmp\level_1_run_0.bin

Removed: tmp\level_0_run_0.bin

Removed: tmp\level_0_run_1.bin

Removed: tmp\level_1_run_0.bin

```

## Особенности реализации

  

### Почему используется бинарный формат

  

Бинарный формат выбран потому, что лента состоит из ячеек одинакового размера.

  

Каждый элемент имеет тип `std::int32_t` и занимает 4 байта.

  

Это позволяет легко вычислять положение текущей ячейки в файле:

  

```text

currentPosition * sizeof(std::int32_t)

```

  

Такой подход ближе к модели ленты с фиксированными ячейками, чем обычный текстовый файл.

  

### Почему нужен `tape_tool`

  

Основная программа должна работать с лентой, а не с обычным текстовым файлом.

  

Но вручную создавать и читать бинарные файлы неудобно.

  

Поэтому добавлена вспомогательная утилита `tape_tool`.

  

Она не участвует в алгоритме сортировки, а только помогает проверять программу:

  

```text

txt/input.txt -> bin/input.bin

bin/output.bin -> txt/output.txt

```

  

### Почему временные ленты называются через `level` и `run`

  

Временные файлы называются по схеме:

  

```text

level_<номер_уровня>_run_<номер_ленты>.bin

```

  

Например:

  

```text

level_0_run_0.bin

level_0_run_1.bin

level_1_run_0.bin

```

  

`level_0` — это первые отсортированные блоки, полученные из входной ленты.

  

`level_1` — это результат слияния лент уровня `0`.

  

`level_2` — это результат слияния лент уровня `1`.

  

Такой подход позволяет не хранить список всех временных лент в памяти. Программа просто вычисляет путь к нужной временной ленте по номеру уровня и номеру ленты.

  

### Как учитывается ограничение памяти

  

Ограничение памяти учитывается при создании начальных отсортированных блоков.

  

Размер блока считается так:

  

```text

blockSize = memoryLimitBytes / sizeof(ITape::ValueType)

```

  

Например, если:

  

```text

memoryLimitBytes = 12

sizeof(ITape::ValueType) = 4

```

  

то:

  

```text

blockSize = 3

```

  

Значит, программа будет читать максимум 3 числа за раз.

  

После сортировки этот блок записывается во временную ленту, память освобождается, и программа читает следующий блок.

  

При слиянии временных лент программа не загружает ленты целиком в память. Она хранит только текущие значения двух сливаемых лент.

  

### Как обрабатываются одинаковые числа

  

Одинаковые числа не удаляются.

  

Например:

  

```text

input:  2 4 3 1 3 5

output: 1 2 3 3 4 5

```

  

Если число встретилось во входной ленте несколько раз, в выходной ленте оно тоже будет записано столько же раз.

  

### Что происходит с папкой `tmp`

  

Перед сортировкой папка `tmp` может содержать только `.gitkeep`.

  

Во время сортировки в ней создаются временные ленты.

  

После успешного завершения сортировки временные ленты удаляются.

  

Если программа завершилась с ошибкой, некоторые временные файлы могут остаться в `tmp`. Их можно удалить вручную.

## Итог

  

Проект реализует модель ленточного устройства и сортировку данных в условиях ограниченной оперативной памяти.

  

Основная программа не загружает всю входную ленту в память. Вместо этого она использует внешнюю сортировку слиянием, временные ленты и последовательное чтение/запись через интерфейс `ITape`.

  

Такое решение соответствует условиям задания: есть интерфейс ленты, файловая реализация ленты, конфигурация задержек без перекомпиляции, сортировщик, консольный запуск и юнит-тесты.
